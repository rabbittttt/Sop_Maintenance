# SOP管理

持久目录统一为同级工作区的 `工作台数据/database/sop/`；独立运行与门户运行读取同一位置。可用 `PLANHUB_DATA_ROOT` 指定数据根（相对路径按应用根解析），应用原有显式数据目录参数继续优先。程序发布不携带业务数据库；发布版使用 `planhub-runtime/database/sop/`。共享 Excel 仍在原共享目录，数据库集中不改变业务口径。首次升级必须停服迁移，旧目录改名为 `.pre-central-*` 恢复备份，不再参与运行。

用于维护月度 SOP 计划的本地应用。网页和 Excel 共用同一份计划数据，支持滚动 M+6、锁单对照、版本维护、导入导出与 Excel 快照备份。

## 启动

1. 首次使用时安装 Python 3.11+，将项目放在 `Project/` 下。
2. 同级存在 `../工作台数据/shared/` 时，从 `../工作台数据/shared/订单汇总/` 读取 `鸿蒙智行锁单选配比例分析.xlsx`；没有共享目录时读取 `input_file/`。计划统一通过“网页维护”保存，或从页面导出 Excel、修改后再导入。服务不再监控、回读或生成服务器上的 `SOP计划维护.xlsx`；旧文件保留不动。
3. 双击 `启动工作台.cmd`。环境正常时直接启动；缺少共享环境或 SOP 依赖时，自动创建 `Project/.venv`、安装所需依赖，成功后继续启动，无需单独初始化。服务就绪后自动打开 <http://127.0.0.1:8876/>，启动窗口保持运行。
4. 关闭该命令窗口或按 `Ctrl+C` 即停止工作台，无需独立停止脚本。仅关闭浏览器页面不会停止服务。

重复双击会打开已运行的网页，服务仍由第一次启动的窗口控制。旧版隐藏后台进程会在新入口首次启动时核对工作目录、进程身份及端口后切换；其他服务不受影响。命令行也可运行 `../.venv/Scripts/python.exe server.py --open-browser`；`./start-sop.ps1 -NoBrowser` 适合不自动打开网页的前台运行。

启动脚本默认从自身位置向上定位名为 `Project` 的工作区，只使用其 `.venv`（Windows 为 `.venv/Scripts/python.exe`，其他系统为 `.venv/bin/python`）。Project 的上级目录可以任意改变；嵌套项目也使用同一个共享环境，不再优先项目自己的 `.venv`，也不会改用 PATH 或 Codex 缓存的 Python。显式 `SOP_PYTHON_PATH` 仍可覆盖；相对值按 SOP 项目根目录解析，例如 `../.venv/Scripts/python.exe`。启动前检查 Python 3.10+ 和 `openpyxl`；健康环境不运行安装、不访问包源。仅默认共享环境缺失或依赖缺失时才自动初始化，并复查成功后继续启动。初始化失败会显示原因并停止；损坏的共享环境保留原样，不删除、不覆盖。显式指定的解释器不可用时直接报错，不自动修改它或改用共享环境。运行 `./start-sop.ps1 -CheckRuntime` 可只检查并显示解释器，不启动服务或修改业务数据。

换电脑时先安装符合工作区依赖要求的 Python 3.11+，复制 Project 时排除旧 `.venv`，再双击 `启动工作台.cmd` 自动重建环境。首次创建共享环境时，初始化程序使用本机 Python 创建虚拟环境；看板及依赖安装始终使用选中的共享环境，不修改系统 Python 的包。`setup-environment.ps1` 是启动器内部使用的准备脚本，只安装本项目 `requirements.txt` 中的 SOP 依赖；需要工作区全部依赖时仍可使用 Project 根的共享初始化入口。初始化需要访问配置的 Python 包源；离线电脑可预先准备对应平台和 Python 版本的依赖包。


`data/service.json`、`data/service.pid` 是旧版后台进程的身份记录，不是当前启动配置。迁移后不要把旧 PID 或旧解释器路径直接改成新值；当前前台入口不依赖这些文件，也不会重新创建它们。旧服务仍在运行时，启动器仅在进程身份核对成功后接管。

**Excel 运行依赖**　网页导出与快照备份统一使用服务的 Python 和 openpyxl。安装 requirements.txt 即可。

**Excel编辑与回填：** 导出时保留明细，可填写“车型总量（不分版本）”行或版本月计划；取消明细后，直接填写车型行的月计划，修改后仍可导入同一份计划。车型总量填写值优先，0表示明确零值，清空并导回后恢复明细自动汇总；未修改的自动汇总值不转成手工总量。锁单、年度合计、品牌合计和总计不作为计划输入。普通车型计划表也可导入，无需版本列或隐藏的导出标识：按品牌、带年款车型和月份匹配，只写入非空计划（含0）；空白及缺行保留原值，不停用车型。带标识的导出表仍按导出基准识别修改，支持清空总量。 网页新导出文件下载前会完成回导校验；旧页面请求缺少必要标识时提示Ctrl+F5刷新，不再返回无法回导的只读下载。 Excel将纯整数保存为文本（如“100”）时也可识别为计划量；对数值单元格紧邻整数的浮点存储误差（如2999.9999999999995）按整数3000导入；真实小数仍报错，不进行通用四舍五入。数量区统一使用普通整数格式（0），不使用货币格式；无效输入会提示具体单元格、车型、月份、实际读取值及原单元格格式，公式不会作为计划值读取。导入校验失败后请保存Excel并重新选择文件，页面会重新读取新内容。

**要货计划：** 在“导入Excel／导出Excel”中选择“要货计划”，按品牌、带年款车型和月份维护；与 SOP 独立保存。“显示要货计划”控制表格中的对应行，并随保存视图保留。空白和缺行保留已有值，0为明确零值；汇总车型填写值优先，否则相加成员单代际，不重复计算。多人同时导入时检查数据版本，发现变化后需刷新核对再导入。年度列统一为“2026总计”等，SOP、锁单和要货计划各自汇总全年1—12月。

**未来车型提前排量：** 先点击“网页维护”，再在车型汇总行点击“新增车型”，直接在原表填写品牌、带年款的车型和各月计划量，无需锁单文件或版本明细。保存后清除原品牌/车型/搜索筛选，便于找到新车型；没有实际锁单时保持空白，不补0。手工车型及计划在刷新、重启和Excel往返后保留，后续真实版本来源出现时仍保留车型总量优先规则。

**锁单口径：** 默认将锁单选配表“版本／数量”行作为分版本锁单，将“交车锁单／数量”行作为车型锁单，两者独立保留原值，不要求合计一致、不分摊。新环境缺少持久目录中的 `source_settings.json` 时也沿用此口径；显式来源配置或命令行参数仍可覆盖默认。已有空值缓存可在更新后到“SOP计划 → 计划设置”点击“刷新销量文件”重新读取，在线计划不变。源文件没有提供的月份仍留空。

**刷新机制：** 锁单、版本和近28天选配比例均从同一份锁单选配文件读取。服务每5分钟检查一次；发现变化后保持稳定1分钟才一起发布，失败则保留上一版并重试。手动点击“刷新销量文件”可立即检查，但同样等待稳定1分钟。SOP计划仅在网页保存或前台导入后变化，不再后台检查维护表；页面可见且未编辑时约每15秒查询更新，显示其他人的修改。首次启动且没有销量缓存时，来源稳定后才出现锁单与选配数据。

**选配拆分：** “选配拆分”标签页以有效月度 SOP 计划量为基数，直接采用锁单选配原表各代际 `by天` 页“近28天／占比”列的显示值，不重新计算比例。动力、电池包、版本、外观、内饰和轮毂分别拆分，不把不同维度的结果相加。页面显示选配数据截止日和实际覆盖天数；近28天来源列不足28个有值日期时不冒充完整样本。汇总代际只用自身源页（也识别规则中的无“汇总”后缀别名），缺少直接来源时在对应车型报错，不从成员比例合成。拆分结果只读，不写回 SOP 计划或锁单；车型总量、汇总总量及已填写版本计划沿用原有优先规则。

**共享代际规则：** 将“SOP维护”和“订单分析”放在同级目录，保留 `../订单分析/scripts/config/shared_config.py` 的 `MERGE_GROUPS` 字典。看板每次读取此相对路径，不硬编码车型映射；规则修改后刷新即生效。页面统一按汇总代际展示，不再选择口径。汇总车型可直接填写月度总量，单代际和版本可在同一张表展开维护；同月汇总填写值优先，清空后恢复成员单代际自动相加（各单代际仍优先其车型总量）。0是明确零值，父子不重复计数。没有单代际计划也可先维护汇总总量。未参与汇总的车型保留原有独立年款。规则缺失或无效时会明确报错，不混用旧目录。车型配置的「汇总规则」可预览并发布到同一份脚本；SOP 按 Python 源文件的编码声明读取，支持带 BOM 的 UTF-8 和声明为 GBK 的文件。

**输入路径：** `--source-dir`（数据导入命令）或网关 `source_dir` 显式配置优先；默认读取顺序为 `SOP_SOURCE_DIR`、`SHARED_DATA_ROOT/订单汇总`、数据根的 `shared/订单汇总`（数据根由 `PLANHUB_DATA_ROOT` 指定，默认 `../工作台数据`），最后仅在同级共享根不存在时兼容 `input_file/`。`SOP_SOURCE_DIR` 和 `SHARED_DATA_ROOT` 支持相对 SOP 项目根目录的路径，例如 `SHARED_DATA_ROOT=../工作台数据/shared`；也兼容绝对路径，不随启动时的当前目录改变。显式指定的共享根或已存在的共享根缺少订单文件时会报告缺失，不改读旧副本。订单汇总目录只提供只读输入；数据库和规则仍由原项目维护。其他汇总报表不会加入 SOP 销量计算。

使用共享数据时，无需创建或保留本项目的空 `input_file/` 目录。该目录仅用于没有共享根的独立运行场景，届时按需创建并放入实际输入文件。

**多人维护：** 所有人访问同一套服务及数据库。网页按单元格版本检查冲突，批量保存整批成功或回退；不同项可分别保存。Excel 按导出原值、填写值、数据库值合并。冲突确认绑定文件、操作人和核对时的数据版本，期间计划、车型或规则有变化必须重新核对；无关项变化也可能使待确认失效。确认后重复请求复用原结果，不重写数据。可见且未编辑的页面约每15秒检测新保存，编辑中的草稿不被刷新替换。从门户进入时按外层传入的账号记录维护人。在「操作记录」可按业务类型查看维护账号、操作时间和变更内容。

**个人视图：** 已存视图和默认视图保存在 SOP 数据库中，按当前登录账号区分。同一账号在其他电脑打开同一工作台时可以使用这些视图。浏览器中有旧视图时，可点击「导入本机视图」带入当前账号，数据库里已有的同名视图会保留。

**旧计划表配置：** `plan_file`、`--plan-file`、`SOP_PLAN_DIR` 保留配置兼容，当前服务不再读写该维护文件。已有数据继续以数据库为准；需导入旧文件时在页面选择上传。

**数据与规则路径：** `SOP_DATA_DIR`（默认 `../工作台数据/database/sop`）和 `SOP_SHARED_CONFIG`（例如 `../订单分析/scripts/config/shared_config.py`）的相对值也按 SOP 项目根目录解析。服务默认数据库目录及数据导入命令默认输出遵循 `SOP_DATA_DIR`；显式 `--data-dir` / `--output` 优先，网关 `data_dir` / `plan_file` 继续保持既有最高优先级和绝对路径校验。运行时会解析为绝对路径；不需要在本地配置中写死盘符。

### 资料对账

在现有导航打开“资料对账”，选择月份和当前 SOP 或历史快照作为本轮基准。基准保留当时的 SOP 计划和交车锁单；刷新基准会记录新版本。Excel、消息、截图及旧资料台 JSON 备份导入后均进入待确认。截图识别在浏览器内离线运行，保存时将原图作为对账证据交给 SOP 服务。

共享 Excel 来源使用现有订单来源目录，以及默认共享根下的 `对账资料/`（存在时）。可用 `SOP_RECONCILE_DIR` 指定其他资料目录，相对路径按 SOP 项目根解析。源文件只读，选择新版本后需重新确认记录。对账轮次、资料、确认记录和操作日志保存在现有 SOP SQLite 数据库中。对账不回写正式计划，结果可导出为 Excel 或文本摘要。

## 单一源码与门户接入

本仓库是 SOP 唯一业务源码，原有独立启动方式保留。门户以前缀代理方式接入，或消费本仓库构建的发布产物。身份、只读与数据路径配置参见 [门户接入说明](PORTAL-INTEGRATION.md)。

### iframe 账号接入

外层系统在**工作台 iframe** 的 `load` 事件里发送当前账号，工作台保存本次页面会话的账号并转发给 SOP。切换账号后 SOP 重新加载，清除上一账号的草稿和视图。

```js
iframeRef.value?.contentWindow?.postMessage(
  { account, roleCode, roleName: ROLE[roleCode] },
  new URL(iframeRef.value.src, location.href).origin
);
```

工作台与 SOP 同源时，最外层系统可以跨源，无需设置 `SOP_PARENT_ORIGIN`。仅当 SOP 的直接父窗口跨源时，设置该变量为直接父窗口的来源。本地启动或本机预览直接打开工作台时，SOP 以 `local-debug` 测试维护和个人视图。

收到三个字段后，SOP 使用 `account` 记录网页维护、Excel 导入和个人视图归属。身份由外层声明，SOP 不另查账号目录。外层代理仍校验部门访问和服务写入开关。原有历史记录按原账号保存。
